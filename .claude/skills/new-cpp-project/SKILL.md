# Новый проект C++ по спецификации

Аргумент — имя проекта в PascalCase (например, `LogFilter`). Второй аргумент,
необязательный, — каталог назначения; по умолчанию `../<имя в нижнем регистре>`.

## Порядок действий

1. **Прочитать `SCAFFOLD.md` целиком.**  
   Это техническое задание. Отступать от него нельзя, дополнять своими решениями — тоже. Если для какого-то файла или настройки спецификация не даёт однозначного ответа, остановитесь и задайте вопрос пользователю: ответ должен быть внесён в спецификацию, а не остаться в рамках одной сессии диалога. Файлы текущего репозитория образцом не считать: скилл должен давать абсолютно идентичный результат из любого каталога.
2. **Проверить чистоту каталога назначения.**  
   Убедитесь, что каталог назначения пуст или ещё не существует. Если в нём уже есть файлы, остановитесь и запросите подтверждение пользователя.
3. **Сгенерировать структуру проекта.**  
   Создать все файлы из раздела «Структура» с подстановкой `<Name>`: каталог `src/<Name>`, `project(<Name>)`, `HeaderFilterRegex`, `PROJECT_NAME` в Doxyfile, `site_name` в mkdocs, заголовок README, `title` в `config.json`, приветствие в `main.cpp` и ожидания в тестах.
4. **Провести сквозное локальное тестирование.**  
   Проверить результат самостоятельно прямо из каталога проекта в строгом порядке, останавливаясь на первой ошибке и исправляя конфигурационные файлы:
   * `python automation/generate_project_files.py`
   * `python automation/build_debug.py`
   * `python automation/run_tests.py`
   * `python automation/format_files.py --check`
   * `python automation/run_tidy.py`
   * `python automation/run_asan.py`
   * `python automation/build_docs.py`
5. **Инициализировать систему контроля версий Git.**  
   Выполнить `git init`, добавить файлы в индекс и создать первый чистый коммит `chore: project scaffold`. Ничего не отправлять в удалённый репозиторий.
6. **Сформировать отчёт для пользователя.**  
   Сообщить путь к проекту, список созданных модулей, статус каждой проверки одной строкой и команду финальной автоматической приёмки:  
   `python <курс>/checks/scaffold.py <каталог>`.

## Жёсткие правила генерации

- Имена целей и путей строятся строго как производные от `<Name>`. В сгенерированном коде не должно оставаться захардкоженных имён вроде `App`, `Template` или `Example`, если только проект явно не назван так пользователем.
- Все версии инструментов, библиотек и экшенов берутся строго из спецификации: никаких спонтанных «обновлений» или устаревших пакетов.
- Комментарии в C++, CMake и Python пишутся на английском языке: краткие, объясняющие причину решения, а не пересказывающие очевидный синтаксис.
- Никаких лишних файлов, не описанных в спецификации: не добавлять лицензии, файлы `CONTRIBUTING.md`, лишние примеры или альтернативные конфиги.
- Если проверка не проходит из-за дефекта в формулировке спецификации, агент обязан остановиться: спецификацию правит разработчик.
